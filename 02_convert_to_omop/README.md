# Step 2: Convert `pgs_calculations_work` to the OMOP CDM `measurement` table

The SQL script
[measurement-calculations-pgs-scores.sql](measurement-calculations-pgs-scores.sql)
copies the rows loaded in [step 1](../01_load_pgs_scores/README.md) into the OMOP CDM
`measurement` table of the staging schema.

Each row of `prs_measurement` becomes **two** `measurement` rows:

| Insert | `value_as_number` | Concept mapping used |
|---|---|---|
| 1. PGS score | `pgs_score` | `source_to_concept_map` rows with `est_source_code_type = 'pgs_score'` |
| 2. PGS score percentile | `pgs_score_percentile` (decile 1–10) | `source_to_concept_map` rows with `est_source_code_type = 'pgs_score_percentile'` |

## Process

For each of the two inserts the script:

1. reads `<pgs_calculations>.prs_measurement`, skipping rows without a PGS ID or value,
2. joins `person` on `prs_measurement.patient_id = person.person_source_value`.
   Patients who are not in the OMOP `person` table are skipped (inner join),
3. looks up the PGS ID (`measurement_source_value`, e.g. `PGS000001`) in
   `source_to_concept_map.source_code` to get the concept IDs (left join),
4. inserts the rows into `measurement` (`SELECT DISTINCT`, so identical rows are inserted once).

## Input

**Table `<pgs_calculations>.prs_measurement`**, written by step 1:

| Column | Content |
|---|---|
| `patient_id` | Patient ID, matched to `person.person_source_value` |
| `measurement_source_value` | PGS ID, e.g. `PGS000001` |
| `pgs_score` | Polygenic score (`SUM` from pgsc_calc) |
| `pgs_score_percentile` | Decile 1–10 of the score within the same PGS ID |
| `calculation_date` | Date the scores were calculated (not used by this step; the measurement date comes from `:observation_time_start` and the birth date) |

**Tables in the `<ohdsi>` schema:**

- `person`: must already contain the patients.
- `source_to_concept_map`: must contain the PGS concept mappings. This table has the
  extra column `est_source_code_type`, which the standard OMOP CDM table does not have.
  An example (not a complete mapping) is in
  [source_to_concept_map_example/source_to_concept_map.csv](source_to_concept_map_example/source_to_concept_map.csv):
  two rows for each of 50 PGS IDs (`PGS000001`–`PGS000050`). The file has no header row.

  Each PGS ID has its own source concept ID for the score and for the percentile,
  so the two kinds of `measurement` rows can be told apart:

  | Row type (`est_source_code_type`) | `source_concept_id` | Example for `PGS000001` |
  |---|---|---|
  | `pgs_score` | `204` + PGS number | `2040000001` |
  | `pgs_score_percentile` | `205` + PGS number | `2050000001` |

  ```
  PGS000001,2040000001,PGS scores,pgs_score,PRS77_BC Breast cancer,,0,None,,,,,2026-09-18,2099-12-31,,false
  PGS000001,2050000001,PGS score percentile,pgs_score_percentile,PRS77_BC Breast cancer [Percentile],,0,None,,,,,2026-09-18,2099-12-31,,false
  ```

## Output

Rows in `<ohdsi>.measurement`:

| Column | Value |
|---|---|
| `measurement_id` | Not set by the script; must be generated by the table (identity/sequence) |
| `person_id` | `person.person_id` |
| `measurement_concept_id` | `source_to_concept_map.target_concept_id` (`0` in the example mapping) |
| `measurement_date`, `measurement_datetime` | The later of `:observation_time_start` and the person's birth date |
| `measurement_type_concept_id` | `32880` (Standard algorithm) |
| `operator_concept_id` | `4172703` (`=`) for scores; not set for percentiles |
| `value_as_number` | `pgs_score` or `pgs_score_percentile` |
| `value_source_value` | Same value as text |
| `measurement_source_value` | PGS ID, e.g. `PGS000001` |
| `measurement_source_concept_id` | `source_to_concept_map.source_concept_id` |
| `datasource` | `'pgs_calculations'` (custom column, not in the standard OMOP CDM) |

## How to run

Run step 1 first. Then run the script with `psql`, passing the three variables it uses:

| Variable | Meaning | Example |
|---|---|---|
| `ohdsi` | OMOP staging schema with `measurement`, `person` and `source_to_concept_map` | `ohdsi_staging` |
| `pgs_calculations` | Schema written by step 1 | `pgs_calculations_work` |
| `observation_time_start` | Earliest measurement date, as a quoted date literal | `"'2000-01-01'"` |

```bash
psql -h "$DB_HOST" -p "$DB_PORT" -U "$DB_USER" -d "$DB_NAME" \
  -v ON_ERROR_STOP=1 --single-transaction \
  -v ohdsi=ohdsi_staging \
  -v pgs_calculations=pgs_calculations_work \
  -v observation_time_start="'2000-01-01'" \
  -f 02_convert_to_omop/measurement-calculations-pgs-scores.sql
```

`observation_time_start` is put into the SQL as written, so it must include the
single quotes. `ON_ERROR_STOP` and `--single-transaction` make sure the script
inserts either both kinds of rows or nothing.

The script only inserts rows. The staging tables are emptied and created in
other steps of the ETL, before this script runs.
